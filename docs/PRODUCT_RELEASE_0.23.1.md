# Product Release 0.23.1

## Цель релиза

Довести аналитическое ядро до пользовательского продукта, который можно открыть с телефона, настроить через окно и запустить без ручного редактирования `.env`, Alembic-команд и переноса файлов.

## Реализовано

- Полное исходное дерево размещено в GitHub, транспортные архивы больше не являются основой репозитория.
- Публичный интерактивный эмулятор опубликован через GitHub Pages.
- Control Center содержит мастер первичной настройки Telegram, PostgreSQL, Workspace, источников и параметров анализа.
- Конфигурация и секреты сохраняются отдельно от репозитория с правами файла `0600`.
- Добавлены проверки Telegram Bot Token, API ID/API Hash, StringSession и PostgreSQL.
- Доступны применение миграций, bootstrap Workspace, запуск, остановка и перезапуск runtime.
- Добавлен production owner-gate: публичными остаются только health/readiness и эмулятор; Control Center и управляющие API требуют внешнюю Basic-аутентификацию и внутреннюю сессию администратора.
- Render Blueprint автоматически запускает `app.setup.secure_proxy` и запрашивает `OWNER_GATE_PASSWORD` при развёртывании.
- Добавлены unit- и HTTP integration-тесты owner-gate.
- GitHub Actions проверяет исходники и публикует эмулятор.

## Пользовательский сценарий

1. Открыть публичный эмулятор и пройти демонстрационный workflow.
2. Нажать Deploy to Render в README.
3. Задать `OWNER_GATE_PASSWORD` в форме Render.
4. Открыть адрес созданного сервиса и войти как `owner`.
5. Создать внутреннего администратора Control Center.
6. Ввести Telegram-ключи, данные Workspace и источников.
7. Запустить проверки подключения, миграции и bootstrap.
8. Нажать «Запустить продукт» и контролировать runtime из окна.

## Проверено

- Source materialization по SHA-256.
- Клонирование рабочего дерева обратно из GitHub.
- Python compileall.
- Полный pytest regression.
- Публичная страница эмулятора.
- Owner-gate: `/health` и `/emulator` отвечают без пароля; `/` отвечает `401` без пароля и `200` с корректными данными.
- Render-конфигурация содержит защищённый entrypoint и обязательный owner-пароль.

## Честные ограничения

- Финальное создание сервиса в конкретном Render-аккаунте требует авторизации владельца хостинга; пароль нельзя безопасно зафиксировать в публичном GitHub-репозитории.
- Реальные Telegram credentials не хранятся в репозитории и должны вводиться владельцем в Control Center.
- Полевой smoke-test конкретного Telegram-аккаунта выполняется после ввода его API ID/API Hash/StringSession.
- Постоянное хранение на облачном хостинге зависит от выбранного плана PostgreSQL и persistent disk.
